# Platform API v1

The bearer API under `/api/v1` lets an app call Platform with the OIDC access token of a Platform admin, such as LibreDB Mobile after its sign-in.
It exists in self-hosted mode only: cloud mode signs in with a password and has no OIDC issuer.
`PLATFORM_API_AUDIENCE` turns it on, and `docs/deploy/platform-runtime.md` lists it with `PLATFORM_API_CLIENT_IDS`.
With the API off, every `/api/v1` route answers 404 `API_DISABLED`.

## Authentication

Every request carries `Authorization: Bearer <access token>`, and no route reads the session cookie of the web console.
The token is a plain OIDC access token, checked with standard JWT rules against the keys that the `jwks_uri` of `${AUTH_KEYCLOAK_ISSUER}/.well-known/openid-configuration` names:

- an asymmetric signature (RS, PS, ES or EdDSA), never `none` or an HS algorithm;
- a header `typ`, when present, of `JWT` or RFC 9068's `at+jwt`, and a `typ` claim, when the issuer sets one as Keycloak does, of `Bearer`, so an ID token or a refresh token that holds the audience never passes;
- `iss` equal to `AUTH_KEYCLOAK_ISSUER`;
- `aud` holding `PLATFORM_API_AUDIENCE`;
- `azp` among `PLATFORM_API_CLIENT_IDS`;
- `exp` present and `nbf`, when present, with at most 30 seconds of clock skew;
- `sub` and `email` present;
- the role claim `PLATFORM_ROLE_CLAIM` holding `PLATFORM_ADMIN_ROLE`, the same rule as the web sign-in.

The caller is always a Platform admin of the install tenant with every permission, the same user a Keycloak web session gets, and a caller never names a tenant.
The first call of an account provisions its Platform user and takes an admin seat exactly as its first web sign-in does, so the license can refuse it.
An app takes Platform's rights from `GET /api/v1/me`, never from the claims of its token.

Unlike a web session, a bearer request is not rechecked against the Keycloak directory.
That recheck exists to end a long-lived cookie session, and the short lifetime of the access token ends a bearer's access instead.

One token serves Studio and Platform: the mobile client's access token carries both audiences, `libredb-studio-api` and `libredb-platform-api`.
Studio could therefore replay an admin's token to Platform within its lifetime.
This release accepts that, because only a token of an account with the admin role passes, that account can do the same in the web console, and the access token is short-lived.

## Errors

Every error answers with the body `{ "error": { "code": "<CODE>", "message": "<text>" } }`, and no message carries the token or a claim value.

| Status | Code | When |
| --- | --- | --- |
| 401 | `BEARER_INVALID` | No bearer token, or one whose signature, issuer, audience, client, lifetime or claims fail; the answer carries `WWW-Authenticate: Bearer error="invalid_token"`. |
| 403 | `ADMIN_ROLE_REQUIRED` | A valid token whose role claim lacks the admin role. |
| 403 | `LICENSE_ADMIN_SEATS`, `LICENSE_EXPIRED`, `LICENSE_INVALID` | The first call of an account, when the license refuses its admin seat. |
| 503 | `IDENTITY_PROVIDER_UNAVAILABLE` | The keys of the issuer cannot be read; never a 401, so an app does not sign its user out over an outage. |
| 404 | `API_DISABLED` | Cloud mode, or `PLATFORM_API_AUDIENCE` unset. |
| 400 | `VALIDATION_FAILED` | Invalid input; the error also carries `fieldErrors`, the messages of each field. |
| 503 | `DIRECTORY_UNAVAILABLE` | A route that reads the Keycloak directory, and Keycloak does not answer. |
| 500 | `INTERNAL_ERROR` | Any other failure, logged by Platform. |

Any other refusal of a route answers with its own code and status, such as 404 `NOT_FOUND`.

## Endpoints

### `GET /api/v1/me`

The caller's Platform user, its rights and the install tenant.

```json
{
  "id": "<users.id>",
  "email": "alice@example.com",
  "name": "Alice",
  "roles": ["PLATFORM_ADMIN"],
  "permissions": ["connection.view", "..."],
  "tenant": { "id": "<tenants.id>", "name": "Acme", "slug": "default" }
}
```

### Grants

These routes do what the access panel of a connection does in the web console, with the same checks.
Each grant they set or revoke records an admin action with channel `api`, where the web console records `web`.

#### `GET /api/v1/connections`

The connections of the install tenant, newest first, with no credential, sealed value or host.
`status` is `active` or `inactive`, and only a connection with a write credential can be granted `write`.

```json
{
  "connections": [
    { "id": "<id>", "name": "Orders", "engine": "postgres", "status": "active", "hasWriteCredential": true }
  ]
}
```

#### `GET /api/v1/directory/users?q=<text>&page=<n>`

One page of 20 Keycloak users that a grant can name, the answer of the grant picker.
`q` matches anywhere in the username, first name, last name or email, and an empty or absent `q` lists every user; `page` counts from 1.
`studioRole` is `admin`, `user` or null, a disabled user has `enabled` false, and `needsSeat` is true when a grant on an active connection would take a user seat of the license.

```json
{
  "users": [
    {
      "id": "<keycloak user id>",
      "username": "bob",
      "email": "bob@example.com",
      "firstName": "Bob",
      "lastName": null,
      "enabled": true,
      "studioRole": "user",
      "needsSeat": false
    }
  ],
  "page": 1,
  "total": 1
}
```

#### `GET /api/v1/connections/{id}/grants`

The grants of a connection, by username.
`grantedBy` is the Platform user who last set the grant, at `grantedAt`.

```json
{
  "grants": [
    {
      "id": "<grant id>",
      "subject": "<keycloak user id>",
      "subjectUsername": "bob",
      "subjectEmail": "bob@example.com",
      "level": "read",
      "expiresAt": "2027-02-01T00:00:00.000Z",
      "grantedBy": { "id": "<users.id>", "name": "Alice", "email": "alice@example.com" },
      "grantedAt": "2027-01-01T00:00:00.000Z"
    }
  ]
}
```

#### `PUT /api/v1/connections/{id}/grants/{subject}`

Creates the grant of the Keycloak user `subject` on the connection, or replaces the grant that user has, and answers 200 `{ "id": "<grant id>" }`.
The body is `{ "level": "read" | "write", "expiresAt": "<ISO 8601>" | null }`, both fields required, and `null` makes a grant that does not expire.

#### `DELETE /api/v1/connections/{id}/grants/{grantId}`

Revokes the grant and answers 204 with no body.
The last segment is the grant id, as the list of grants gives it, and not the subject that a `PUT` takes.

#### Refusals of the grant routes

| Status | Code | When |
| --- | --- | --- |
| 404 | `NOT_FOUND` | The install tenant has no such connection, or the connection has no such grant. |
| 400 | `VALIDATION_FAILED` | On `level`: `write` on a connection without a write credential. On `subject`: a user Keycloak does not know, or one it has disabled. On `expiresAt`: a time that is not in the future. |
| 403 | `LICENSE_USER_SEATS`, `LICENSE_EXPIRED`, `LICENSE_INVALID` | A grant that would take a user seat the license refuses. |
| 503 | `DIRECTORY_UNAVAILABLE` | Keycloak does not answer the directory read of a `PUT` or a directory search; a revoke reads nothing from Keycloak. |

#### `PATCH /api/v1/connections/{id}`

Enables or disables a connection, as the `active` switch of the connection form does in the web console, with the same checks.
The body is `{ "active": true | false }`, and `active` is the only field the route takes: any other field, such as `name`, `definition` or a credential, is refused, so the route never reaches a definition or a credential.
The answer is 200 with the connection in the shape of one item of `GET /api/v1/connections`:

```json
{ "id": "<id>", "name": "Orders", "engine": "postgres", "status": "inactive", "hasWriteCredential": true }
```

A change records the admin action `connection.update` with channel `api` and the connection before and after it, in the transaction of the change.
Setting the value the connection already has answers 200 and changes nothing, and records no admin action.

Disabling never deletes the connection or its grants.
`bridge.connections_v1` stops publishing the connection and `bridge.grants_v1` its grants, and enabling it again publishes the same grants, which can take user seats of the license.
Studio stops serving a disabled connection at its next governance reload: the change notification of the commit triggers that reload, typically within a second, and Studio's `GOVERNANCE_REFRESH_MS`, 30 seconds by default, bounds it when the notification is lost.
So disabling is fast but not instant, and the route does not end a Studio query that is already running.

The route refuses with:

| Status | Code | When |
| --- | --- | --- |
| 404 | `NOT_FOUND` | The install tenant has no such connection, or the connection is deleted. |
| 400 | `VALIDATION_FAILED` | `active` is missing or not a boolean, which `fieldErrors` reports on `active`, or the body holds another field, which `fieldErrors` reports on the empty key `""`. |
| 403 | `LICENSE_INVALID`, `LICENSE_EXPIRED`, `LICENSE_USER_SEATS` | Enabling a connection under a license that could not be verified or has expired, or one whose grants would need more user seats than the license allows; the license never refuses a disable. |

### `GET /api/v1/audit`

The governed query events of the install tenant, newest first, with the filters, the checks and the answer of `GET /api/db/audit` of the web console.
Every filter is an optional query parameter, and the tenant is never one of them:

| Parameter | Value |
| --- | --- |
| `subject` | The subject of the events, the Keycloak `sub` of the account that ran the statement. |
| `connectionId` | The `id` of a Platform connection. |
| `source` | The source Studio recorded, such as `key-scan`. |
| `statementType` | A statement type, such as `SELECT`. |
| `status` | `success`, `error`, `cancelled` or `refused`. |
| `from`, `to` | An ISO 8601 time that bounds `startedAt`. |
| `search` | Text that the statement contains, ignoring case, at most 200 characters. |
| `limit` | The page size, 1 to 200, 50 by default. |
| `offset` | The number of events to skip, 0 by default. |

```json
{
  "events": [{ "eventId": "<event id>", "startedAt": "2026-10-01T09:30:00.000Z", "subject": "<sub>", "status": "success", "...": "..." }],
  "total": 41
}
```

`total` counts every event that the filters select, so `offset + limit < total` means another page exists.
The route refuses with:

| Status | Code | When |
| --- | --- | --- |
| 403 | `PLAN_FEATURE_REQUIRED` | The plan of the install tenant lacks the audit log, checked before anything else. |
| 403 | `PERMISSION_DENIED` | The user lacks `audit.view`. |
| 400 | `VALIDATION_FAILED` | A filter is invalid; the message names each such filter, and `fieldErrors` holds their messages. |
